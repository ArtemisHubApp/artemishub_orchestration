# Plano 2: ADRs do orquestrador no `artemishub_docs`

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** registrar como ADRs, no site do `artemishub_docs`, as decisões do design do orquestrador, e alinhar o orquestrador ao caminho real dos ADRs.

**Architecture:** os ADRs são páginas Markdown do MkDocs. Cada tarefa acrescenta um grupo de ADRs, a linha de cada um na tabela do índice e a entrada no `nav`, e o `mkdocs build --strict` precisa continuar verde. A última tarefa corrige o orquestrador, que hoje aponta para uma pasta que não existe.

**Tech Stack:** MkDocs + Material (`artemishub_docs/mkdocs.yml`), Markdown, Python 3 (scripts e testes do orquestrador).

**Spec:** `docs/superpowers/specs/2026-11-17-artemishub-orchestration-design.md`, seção 6.9 e as seções que cada ADR resume. Índice: `docs/superpowers/plans/2026-11-17-00-indice.md`.

## Achado que muda o spec

O `artemishub_docs` já tem uma seção de ADRs: `docs/adr/` (`index.md` + `002-framework-multiagente.md`). A `ADR-001` está reservada para a stack (issue `artemishub_docs#3`). O spec 6.9 previa uma pasta nova, `docs/arquitetura/decisoes/`, com numeração `0001` a `0008`. **Decisão deste plano:** seguir a convenção que já existe. Os ADRs ficam em `docs/adr/`, com números de 3 dígitos a partir de **003**. A Task 5 corrige o orquestrador (`AGENTS.md` e `artemis-sdd`), que cita o caminho antigo.

## Global Constraints

- Pasta e nomes: `artemishub_docs/docs/adr/NNN-slug.md`, com `NNN` de 3 dígitos. ADRs **003 a 010**. Não mexer nos ADRs 001 e 002.
- Formato de cada página, igual ao ADR-002:
  - frontmatter com `origem: "..."`;
  - título `# ADR-NNN: <decisão em minúsculas>`;
  - os bullets `**Status:**`, `**Data:** 17/11/2026` e `**Issues:**`;
  - as seções `## Contexto`, `## Decisão`, `## Alternativas` e `## Consequências`, e `## Fontes` quando houver link externo.
- Status inicial: `proposto (aguardando aprovação do time)`. Passa a `aceito` quando o time aprova o PR.
- Cada ADR tem no máximo cerca de 60 linhas, em português, curto e sem jargão desnecessário. É para quem não estava na conversa de design.
- Todo ADR cita o orquestrador com o link `https://github.com/ArtemisHubApp/artemishub_orchestration` e a seção do spec que ele resume.
- `docs/adr/index.md`: uma linha por ADR na tabela existente (`| [ADR-NNN](NNN-slug.md) | decisão | status |`), em ordem numérica.
- `mkdocs.yml`: as entradas ficam dentro de `Arquitetura > Decisões (ADRs)`, depois do ADR-002, no formato `- ADR-NNN Título curto: adr/NNN-slug.md`.
- Gate de cada tarefa: `mkdocs build --strict` sem erros nem avisos. **Nesta sessão o plugin `glightbox` não está instalado** (ruling R1). Por isso a verificação local usa uma cópia temporária do `mkdocs.yml` sem esse plugin, com o comando exato da Task 1. O CI de docs roda o build real.
- Fluxo das regras do projeto:
  - uma issue no `artemishub_docs` para este trabalho;
  - branch `docs/<nº>-adrs-orquestrador`, criada a partir de `origin/staging`, ou de `origin/main` enquanto não houver `staging`;
  - PR com `Closes #<nº>`.
  - Na Task 5, outra issue e outro PR no `artemishub_orchestration`.

## Review Focus

1. **Link quebrado no `--strict`**, por exemplo um link relativo para `../arquitetura/x.md` que não existe. O build tem que falhar, e a tarefa só fecha com o build limpo.
2. **Numeração colidindo com um ADR novo do time.** Se alguém mergear um ADR-003 antes deste PR, este plano renumera os seus ADRs para depois do último existente. Confira `ls docs/adr/` no `origin/staging` (ou `main`) antes de abrir o PR, na Task 4.
3. **ADR que contradiz o que foi implementado.** Exemplos: ele diz que a fonte da `artemis-sdd` é o `.claude/` (o spec antigo dizia isso; o certo é `.agents/`), ou cita `gitleaks-action`, que foi trocada pela CLI. Cada ADR é conferido contra o código do orquestrador em `origin/staging`, e não só contra o spec.
4. **Leitora que não conhece git avançado:** cada ADR explica o porquê em linguagem simples, e o termo técnico aparece junto da explicação.
5. **Orquestrador apontando para a pasta errada:** depois da Task 5, nenhum arquivo do orquestrador fora de `docs/superpowers/` cita `arquitetura/decisoes`, e um teste garante isso.
